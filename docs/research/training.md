# Проверка обучаемости

**Дата замера:** 2026-09-08.

Вопрос: действительно ли обучаются обе обучаемые величины — матрица судьи и векторы кандидатов.
Замеры без обращений к модели, на синтетических спецификациях: проверяется арифметика обучения,
а не разметка.

## Судья: повторить оценку человека

`JudgeTrainer` подгоняет `TransformerW` под оценку человека: ошибка — квадрат расхождения между
косинусом судьи и оценкой, спуск по градиенту (SGD, скорость 1,0).

Случай подобран так, чтобы судья **ошибался**: факт формально почти совпадает с заказом (косинус
1,0000), но человеку ответ не понравился.

| Шаг | Оценка судьи | Ошибка |
|---|---|---|
| до обучения | 1,0000 | 0,999952 |
| 25 | 0,0000 | 0,000000 |
| 100 | 0,0000 | 0,000000 |
| 500 | 0,0000 | 0,000000 |

Обратный случай (человек доволен, цель 1,0) судья проходит без изменений: он уже прав, и обучение
его не портит.

### Что этот замер НЕ показывает

Один пример, повторённый 500 раз, сходится к этому же примеру, а не к закономерности. Быстрое
падение ошибки означает лишь, что градиент течёт и знак верный.

## Роутер: контрастивное разведение

`RouterTrainer` разводит векторы победителя и соперников на зазор 0,1: понравился ответ — победитель
поднимается над соперниками, не понравился — опускается под них.

Старт: у обоих кандидатов одинаковые векторы, отрыва нет.

| Замер | Значение |
|---|---|
| Отрыв до обучения | 0,0000 |
| Отрыв после 200 шагов | 0,2000 |
| Ошибка | 0,100000 → 0,000000 |
| Порядок в `Env.GetTopK` | изменился на победителя |

Отрыв встал ровно на требуемый зазор и дальше не рос — так и задумано: штраф обнуляется, как только
разрыв достаточен.

## Обучение по выборке

Проверка того, ради чего заводился накопитель: даёт ли обучение на **разных** ходах то, чего не даёт
один пример.

Постановка: два кандидата и два типа задач. За «Писателем» закреплены научные тексты, за «Кодером» —
технические; оба хода получили положительный отзыв. Обучение шло по выборке из накопителя, 100 эпох.

| Замер | Значение |
|---|---|
| Записано ходов / оценено | 3 / 2 (ход без отзыва в выборку не попал) |
| Суммарная ошибка эпохи | 0,2959 → 0,0000 |
| Научная задача | → Писатель |
| Техническая задача | → Кодер |

**Кандидаты специализировались по типам задач.** Это первое, чего одиночный пример показать не мог:
векторы развелись не «вообще», а по признакам задачи, и на новой задаче выбор идёт по её типу.

## Хранилище

| Проверка | Результат |
|---|---|
| Узнано кандидатов при загрузке | 2 из 3 (третий не сохранялся, остался с начальными весами) |
| Расхождение вектора после круга сохранение → загрузка | 0,00E+000 |
| Расхождение матрицы судьи | 0,00E+000 |
| Загрузка весов другой размерности | отклонена с сообщением о размерностях |
| Восстановление трассировки из накопителя | победитель, соперники и 26 координат признаков |

Проверка размерности важна: признаки меняются при добавлении стиля или метрики, и молча взятые веса
прежней длины означали бы обучение поверх мусора. Такое расхождение в этом проекте уже случалось
дважды.

## Известные ограничения

* **Оптимизатор роутера строится на каждый шаг.** Состав кандидатов меняется от хода к ходу, а у
  спуска без импульса нет состояния, которое стоило бы переносить. Для Adam с моментами понадобится
  хранить оптимизатор на кандидата.
* **Обучение идёт во float32** — тензоры автограда считают только в нём, обратная запись в `Matrix`
  и `Vector` идёт через тот же мост. Для весов это несущественно, но точность на границе теряется.
* **Замеры синтетические.** Настоящая проверка — обучение на накопленных реальных ходах с
  человеческими отзывами; таких данных пока нет.
