# Оценка содержания на бизнес-задачах

**Дата измерения:** 2026-09-14. Стенд [harness/BusinessTasks](harness/BusinessTasks), набор задач
[data/business-tasks.json](../../data/business-tasks.json), контрольные пары
[harness/BusinessTasks/control-pairs.json](harness/BusinessTasks/control-pairs.json). Распознавание
задания и замер формы делает `openai/gpt-4o-mini`, судья содержания `openai/gpt-5.2`.

## Зачем

Главная метрика библиотеки сверяла с заказом только форму ответа: объем, разделы, таблицы, стиль,
язык. Таблица есть, отчет есть, список источников есть, и критик ставит «отлично», хотя в таблице
выдуманные цифры, в отчете не та аналитика, а источники не существуют. Для бизнес-задачи главное
как раз наполнение работы. Поэтому у оценки теперь две оси.

- **Форма**: прежние 20 пунктов критика. Итог формы равен доле выполненных пунктов.
- **Содержание**: судья `ContentJudge`, одно обращение к модели по строгой схеме, восемь
  критериев от 0 до 1 с опорными точками и конкретные замечания.

Итоговая оценка `Judge.Assess` берет 0,7 содержания и 0,3 формы; на ней учится роутер. Критерий,
который к задаче не относится, в среднее не входит: у задачи без ограничений нечего выполнять, у
ответа без проверяемых утверждений нечего проверять.

| Критерий | Что проверяет | Откуда взят |
|---|---|---|
| Фактология | атомарные проверяемые утверждения (до 12), средняя вероятность истинности | рейтинг фактологии арены |
| Полнота по сути | раскрыт ли каждый смысловой пункт заказа | GDPval, рубрика MAS |
| Выполнение указаний | доля выполненных явных ограничений | Instruction Following арены, IFBench |
| Верность рассуждений и расчетов | выводы следуют из данных, числа сходятся | аналитическое качество Briefcase у AA |
| Экспертная глубина | уровень, которого ждет специалист | Expert арены |
| Наполнение структуры | таблицы, списки и разделы содержательны | пример владельца |
| Качество источников | источники существуют, по делу, подтверждают утверждения | поисковая арена |
| Пригодность для дела | можно ли отдать результат заказчику как есть | GDPval, работа со знаниями у AA |

Смысловые пункты и явные ограничения выделяет из запроса то же обращение, которым распознается
задание, поэтому полнота проверяется по сути заказа, а не по числу разделов.

Проверка фактов устроена как у арены: утверждение выписывается атомарно, у каждого своя
вероятность. Без веба эту вероятность ставит сама модель-судья, то есть она сама себе фактчекер.
Хост с веб-поиском передает проверку делегатом, и тогда вероятность дает он.

## Набор задач

66 задач, по две на каждый из 33 типов задачи в восьми группах: письма и коммуникации, отчеты и
аналитика, маркетинг и продажи, документы и право, код и ИТ, наука и обучение, творчество и медиа,
консультации и планы. У задачи записаны ожидаемые тип, область, уровень экспертности и смысловые
пункты. В задачах с расчетами входные данные заданы в самом запросе (тарифы, выручка, конверсии,
вклад), поэтому верность ответа проверяется без внешних источников.

## Замер 1. Распознавание задания

| Величина | Значение |
|---|---|
| Задач | 66 |
| Тип задачи угадан точно | **61 из 66 (92%)** |
| Тип задачи попал в свою группу | 62 из 66 (94%) |
| Область угадана | 44 из 66 (67%) |
| Экспертность в своей половине шкалы | 53 из 66 (80%) |
| Выделены смысловые пункты | 66 из 66, медиана 4 на задачу |
| Опора на факты, среднее | 0,73 у экспертных задач, 0,39 у прочих |

Промахи типа задачи осмысленные: финансовый расчет принят за анализ данных, консультация за
объяснение, сценарий рекламного ролика за рекламный текст. В свою группу не попали 4 задачи.

**Область распознается хуже всего, и это слабое место.** 22 промаха, и больше половины из них
одного рода: продажи, маркетинг, кадры и операции модель относит к общей области Business.
Отраслевые категории арены так и устроены (там бизнес, управление и финансы одной категорией),
а функции AutomationBench новые, и описание поля их пока не разводит. Для выбора модели промах
области смягчается типом задачи: коммерческое предложение распознано верно, и прайор по нему
работает. Следующий шаг: опорные примеры в описании поля, как у шкалы терминологии.

## Замер 3. Контрольные пары: форма есть, содержания нет

Четыре задачи, у каждой два ответа одной формы (тот же объем, разделы, таблица, ссылки):
хороший и плохой по содержанию. Весь путь настоящий: задание распознается из запроса, форма
измеряется по ответу, содержание оценивает судья.

| Пара | Изъян плохого ответа | Форма: хороший / плохой | Содержание: хороший / плохой | Итог: хороший / плохой |
|---|---|---|---|---|
| Тарифы | выдуманные цифры в таблице, неверный расчет и вывод | 0,78 / 0,77 | **0,96 / 0,49** | 0,91 / 0,58 |
| Исковая давность | неверные нормы ГК РФ: срок, начало течения, порядок применения | 0,75 / 0,73 | **0,92 / 0,25** | 0,87 / 0,40 |
| Скорость света | ложные факты и выдуманные источники | 0,76 / 0,69 | **0,90 / 0,33** | 0,86 / 0,44 |
| Перенос оплаты | нарушены указания: другой срок, оправдания, нет подтверждения | 0,74 / 0,73 | **0,76 / 0,48** | 0,76 / 0,55 |

Сверка формы разводит хороший и плохой ответ на 0,01-0,07, судья содержания на 0,28-0,67.
Итоговая оценка плохих ответов во всех четырех парах ниже 0,6, хороших выше 0,75.

Разные изъяны ловят разные критерии, и это видно по разбору:

- **Тарифы**: верность расчетов 0,99 против 0,10, пригодность для дела 1,0 против 0,1. Замечание
  судьи: «для 40 сотрудников при лимите 10 нужно 4 подписки, то есть 4×990=3 960 руб., а не
  1 980 руб.» Фактология здесь почти не помогает (0,99 против 0,46): утверждения вида «тариф стоит
  990 руб.» верны, ложны выводы из них. Поэтому одной фактологии мало, и критериев восемь.
- **Исковая давность**: фактология 0,94 против 0,02. Судья назвал верные нормы сам: срок три года
  по статье 196, начало течения по статье 200.
- **Скорость света**: фактология 0,93 против 0,15, качество источников 0,85 против 0,10.
- **Перенос оплаты**: фактология одинакова (0,75 и 0,75), потому что изъян не в фактах, а в
  указаниях. Его поймал критерий выполнения указаний: 0,70 против 0,20.

Абсолютные значения формы у хороших ответов около 0,75, а не единица: распознанный заказ ждет,
например, больше абзацев и разделов, чем в коротком ответе. Для пары это не важно, важно, что
форма у обоих ответов одинакова.

`claude-haiku-4.5` уступает остальным в фактологии и расчетах, `deepseek-v4-flash` в расчетах

ответах пустых таблиц не было, этот критерий срабатывает на явном браке, как в контрольной паре.

**Прайор рейтингов здесь не различает.** Во всех восьми группах он выбрал `deepseek-v4-flash`:
это самая свежая из четырех моделей, и в рейтингах она опережает три модели 2025 года почти во всех
сериях. Совпадений с лучшим по содержанию 3 из 8, но это совпадения одного выбора на все группы, а
не различение. Прайор отвечает за старт: сильная свежая модель получает ход раньше слабой, а
различие между близкими моделями по группам задач выучивает журнал оценок, в том числе
автоотзывы судьи содержания.

## Ограничения

- Судья содержания без проверки по вебу оценивает факты сам. На контрольных парах этого хватило:
  ложь в нормах права и физических константах он распознал уверенно. На редких фактах, которых
  нет в его знаниях, вероятность будет ближе к середине, и для них нужен делегат проверки.
- Судья и один из кандидатов живого прогона одного поставщика (OpenAI). Перекрестная проверка
  другим судьей не делалась.
- Распознавание делает небольшая модель, и область она определяет верно в двух случаях из трех.
- Набор задач составлен вручную; это 66 задач, а не выборка реальных запросов пользователей.

## Как повторить

```bash
python docs/research/harness/BusinessTasks/business_tasks.py
```

Ключ OpenRouter берется из `OPENROUTER_API_KEY` или из `key.txt` рядом со стендом. Ответы моделей и
оценки кэшируются в `results/cache.json`, повторный прогон бесплатен.
