# Начальные веса кандидатов из внешних замеров качества

**Дата измерения:** 2026-09-14. Полный снимок (152 серии, 3,4 МБ) собран забором вне репозитория,
укороченный до 60 записей на серию лежит в
[data/benchmark-snapshot.json](../../data/benchmark-snapshot.json). Библиотека работает с готовым
снимком: состав источников и разбор их страниц дело локальное, в репозитории живут только снимок и
профили задач по сериям. Каталог OpenRouter взят тем же днем: 445 моделей, из них 349 без вариантов
`:batch`, `:free` и подобных.

## Зачем

Холодный старт роутера задавался одним числом на модель: баллом возможностей из каталога
(контекст, модальности, инструменты). Опорная задача у всех кандидатов была одна, поэтому до
первого обучения они различались только этим баллом и по типам задач не расходились вовсе.
Внешние замеры оценивают модели по сериям, которые ложатся на признаки задачи: язык
программирования, отрасль, фактология по областям знаний, трудность, экспертность, длина диалога,
тип бизнес-задачи.

## Что лежит в снимке

Ключ серии начинается с вида замера: `pref:` для парных предпочтений людей на задачах, `bench:`
для прогонов бенчмарков.

| Вид замера | Что берется | Серий | Строк |
|---|---|---|---|
| Предпочтения, текст | общая серия, экспертная постановка, 8 отраслевых, математика, следование указаниям, многоходовый диалог, творческое письмо, код, трудные запросы (два варианта), длинные запросы, 10 языковых | 28 | |
| Предпочтения, код и поиск | frontend, fullstack, html, react, brand-marketing; поиск | 6 | |
| Предпочтения всего | | **34** | 10 795 |
| Бенчмарки, отраслевые индексы | 6 индексов (финансы и учет, стратегия и операции, право, медицина, инженерия, экономика) и их части, цена задачи, доля рассуждений в ней | 48 | |
| Бенчмарки, передовые модели | фактология по 6 областям знаний, знание 14 языков программирования, 6 бизнес-функций агентной работы и 20 сервисов, 10 отраслей документной работы, аналитика и оформление, практики права | 59 | |
| Бенчмарки, общая таблица | индекс интеллекта, доля ответов без выдумки, следование указаниям, длинный контекст, агент поддержки, экспертные вопросы, офисная работа, код в терминале, научный код, скорость | 11 | |
| Бенчмарки всего | | **118** | 7 877 |

Замера фактологии среди предпочтений нет: метод там описан (атомарные утверждения, проверка
агентами с веб-поиском, доля фактологии 25% в итоговом рейтинге), но вес фактологии переключается
в браузере, а страница отдает общую серию без контроля стиля. Поэтому фактология берется из
прогонов: доля ответов без выдумки есть у 521 модели, по областям знаний у 30 передовых. Прежняя
серия «фактология поиска» на деле была обычной поисковой и называется `pref:search/overall`.

## Как серии становятся замерами

`QualityPrior.FromMeasurements` строит вектор кандидата по парам «признаки задачи, замеренное
качество». `BenchmarkPrior` дает ему такие пары: каждой серии соответствует профиль задачи, а
качество равно доле оценки модели между худшей и лучшей в серии (лидер получает единицу).

Профили лежат в одном файле
[fai_router/data/benchmark_profiles.json](../../Python/fai_router/data/benchmark_profiles.json),
общем для обеих версий: Python читает его как данные пакета, C# как встроенный ресурс. 81 серия
описана 88 профилями. Спецификация задачи собирается слиянием: опорная задача, шаблон (код,
наука, математика, деловая работа, техника) и поправки профиля. Примеры:

| Серия | Профиль задачи |
|---|---|
| `pref:text/expert` | экспертность 0,9, трудность 0,6 |
| `pref:text/instruction-following`, `bench:instructions` | пять явных ограничений |
| `pref:text/multi-turn` | четыре реплики пользователя |
| `pref:text/hard-prompts` | трудность 0,9 |
| `bench:non-hallucination` | опора на факты 0,9 |
| `bench:knowledge/law` | деловая работа, право, юридическое заключение, опора на факты 0,9 |
| `bench:code-language/rust` | код на Rust |
| `bench:workflow/sales` | продажи, коммерческое предложение, три правила |
| `bench:index/finance-and-accounting` | финансы, финансовый отчет, две таблицы, экспертность 0,7 |
| `bench:analysis/analytical` | аналитический отчет и анализ данных |

Серии, которые на признаки задачи не ложатся, в снимке хранятся, но в прайор не идут: части
индексов, оценка оформления, отдельные сервисы агентной работы (признака «какой сервис» у задачи
нет, а модели в такой серии только 30).

## Сопоставление имен

Имена в трех местах различаются: `anthropic/claude-haiku-4.5` в каталоге, `claude-haiku-4-5` в
замерах предпочтений, `claude-4-5-haiku-reasoning` в прогонах бенчмарков. `ModelNames.Canonical`
снимает поставщика, вариант после двоеточия, хвосты усилия, режима, даты и контекста и приводит
старый порядок имени Claude к новому. Из нескольких вариантов одной модели берется тот, у которого
больше голосов, а при равных голосах самый короткий ключ, то есть вариант без суффиксов.

| Величина | Значение |
|---|---|
| Моделей каталога без вариантов | 349 |
| Нашлись в замерах предпочтений | 151 |
| Нашлись в прогонах бенчмарков | 182 |
| Нашлись хотя бы в одном виде замера | **199** |
| Нашлись в обоих | 134 |
| Серий на найденную модель, медиана | 36 из 81 |

По поставщикам (хотя бы в одном виде замера): Anthropic 15 из 15, Z.ai 14 из 14, Moonshot 7 из 7,
DeepSeek 10 из 15, OpenAI 42 из 60, Qwen 35 из 51, Google 17 из 29, Mistral 8 из 19. Не находятся
в основном модели, которых нет ни в одном замере: картинки и звук, размерные варианты Qwen,
линейка `-pro` OpenAI, датированные сборки Mistral.

## Скорость и цена задачи

Скорость в каталоге не публикуется, и раньше каждый кандидат без своих замеров получал 50 токенов в
секунду. Теперь начальную скорость дает серия `bench:speed` (медиана токенов в секунду), она есть у
147 моделей каталога.

Прайс не знает, сколько модель потратит на рассуждение. Цена задачи в прогонах разложена на вход,
рассуждение и ответ, и доля рассуждения (`bench:reasoning-share/<индекс>`) дает начальную поправку
цены: задача дороже прайса ответа в `1 / (1 − доля)` раз, не больше чем в 5 раз. Поправка есть у 23
моделей, у остальных остается единица, а журнал заменяет ее своей, как только наберет цены ходов.

| Модель | Скорость, токенов в секунду | Поправка цены |
|---|---|---|
| claude-opus-5 | 51,2 | 1,18 |
| gpt-6-astra | 59,8 | 1,31 |
| deepseek-v4-pro | 81,3 | 1,42 |
| gemini-3.1-pro-preview | 112,1 | нет данных |

## Что прайор различает

Прогноз прайора (без обучения) на профилях четырех отраслей у четырех передовых моделей:

| Модель | Код | Проза | Право | Финансы |
|---|---|---|---|---|
| claude-opus-5 | 0,95 | 0,95 | 0,97 | 0,88 |
| gpt-6-astra | 1,01 | 0,92 | 0,98 | 0,94 |
| deepseek-v4-pro | 0,74 | 0,89 | 0,63 | 0,64 |
| gemini-3-flash-preview | 0,67 | 0,90 | 0,13 | 0,10 |

Класс модели прайор разводит уверенно, и профиль у каждой свой: `gemini-3-flash-preview` на прозе
почти вровень с флагманами, а в праве и финансах на порядок ниже, у `deepseek-v4-pro` проза
сильнее кода. Прогноз выше единицы у `gpt-6-astra` на коде: это не ошибка, прогноз линейный и
поверх лидерства в сериях кода и знания языков программирования.

## Проверка на стенде качества

В [model-quality-grid.md](model-quality-grid.md) три модели одного класса замерены на четырех типах
задач по форме ответа. Прогноз прайора на тех же типах задач (`Settings.TaskMean` пуст):

| Тип задачи | gemini-2.5-flash | gpt-4.1-mini | claude-haiku-4.5 | Прайор выбрал | Лучший по стенду |
|---|---|---|---|---|---|
| научный | 0,27 | 0,24 | **0,75** | claude-haiku-4.5 | claude-haiku-4.5 |
| детский | **0,40** | 0,38 | −0,35 | gemini-2.5-flash | gemini-2.5-flash |
| деловой | 0,61 | 0,30 | **0,71** | claude-haiku-4.5 | gpt-4.1-mini |
| технический | **0,59** | 0,56 | 0,44 | gemini-2.5-flash | claude-haiku-4.5 |

**Два совпадения из четырех**; на одних предпочтениях не было ни одного. Стенд мерит форму (объем,
разделы, стиль), а замеры мерят содержание и предпочтение людей, поэтому полного совпадения здесь
и не ждали. Проверка по содержанию на 16 бизнес-задачах описана в
[business-evaluation.md](business-evaluation.md).

## Смена размерности

Вектор спецификации вырос с 23 до 104 координат, полный вектор задачи с 25 до 111. Сохраненные
векторы другой длины не подходят: в MAS `RouterCandidateSource` их отбрасывает и кандидат стартует с
прайора замеров, в библиотеке `SqliteWeightsStore.Load` на другой размерности бросает исключение
по замыслу. Задачи без предмета сохранили прежние ненулевые координаты, поэтому косинусы между ними
и оценки судьи формы не изменились: у перечислений предмета первое значение разряда не имеет.
