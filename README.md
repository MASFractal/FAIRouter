# FAIRouter

Библиотека для выбора инструментов, агентов и LLM под конкретную задачу и для оценки того, что
исполнитель выдал.

## Идея

Величина «качество» существует здесь в двух видах, и разница между ними — сигнал обучения.

**Роутер предсказывает** качество до того, как задача исполнена: по одному тексту запроса он
решает, кто справится лучше. **Судья измеряет** качество после: сравнивает фактический ответ с тем,
что заказывали. Расхождение прогноза с фактом учит роутера, расхождение судьи с оценкой человека
учит судью.

Всё остальное в библиотеке — обвязка вокруг этой пары.

## Два контура

### Роутер: выбор исполнителя

```
запрос → признаки → q (прогноз качества) → R (качество / цена / время) → топ-K
```

`Env.GetTopK(текст, кандидаты, k)` ранжирует кандидатов по метрике **R**:

```
        WQ·q − WC·c
R = ─────────────────
      Wt·log(t + 2)
```

где `q` — прогноз качества, `c` — стоимость запроса в долларах по ценам исполнителя
(`DPMTInp`/`DPMTOutp` за миллион токенов), `t` — ожидаемое время ответа (`LenAnswer / TPS`).
Веса `WQ`, `WC`, `Wt` в `Settings` задают курс обмена: роутер вправе сознательно взять модель
слабее, но дешевле и быстрее.

Прогноз качества `q` — скалярное произведение вектора признаков задачи на обучаемый вектор
исполнителя `IdealMatchVector`. У каждого кандидата он свой: это и есть «на каких задачах я хорош».

### Судья: оценка результата

```
ответ → фактическая спецификация → косинус с заказом → оценка
                                 → расхождения по пунктам (критик)
```

Судья работает в двух режимах:

* **Оценка** (`Judge.GetScore`) — косинус между вектором фактической спецификации и вектором
  заказа, пропущенным через обучаемую матрицу `TransformerW`. Одно число, годится как сигнал.
* **Критик** (`Judge.Criticize`) — `DiffSpec` с расхождением по каждому пункту ТЗ отдельно:
  заказано / получено / отклонение. Объясним для человека и не зависит от масштаба координат.

Матрица `TransformerW` нужна потому, что заказ и факт не совпадают буквально даже при отличной
работе: заказали 3000 знаков — хороший ответ даст 2700. Матрица и есть выучиваемое отображение
«что просили» → «как это выглядит, когда сделано хорошо». Единичная на старте означает наивное
«факт обязан совпасть с заказом».

## Спецификация: общий язык заказа и факта

`Specifications` описывает **и** требования к ответу, **и** свойства готового текста — один тип на
обе стороны, поэтому их можно сравнить.

| Откуда берётся | Поля |
|---|---|
| Считается по тексту (`TextMetrics`) | объём в символах и словах, абзацы, разделы, пункты списков, таблицы, блоки кода, формулы, глубина заголовков, средняя длина предложения, читаемость, язык, наличие ссылок |
| Распознаётся моделью (`StyleClassifier`) | стиль, доля терминологии, формальность тона |
| Извлекается из запроса моделью (`LLMRecognitionSpecInput`) | все поля сразу, одним запросом |

Структуру считает арифметика, смысл распознаёт LLM. Стиль (`Style`) участвует в векторе
one-hot-кодом.

### Про нормировку координат

Вектор сравнивается косинусом, поэтому координаты обязаны быть соизмеримы. В сырых единицах объём
в символах давал **97,8% нормы вектора**, и судья мерил только длину: текст в противоположном стиле
получал оценку 0,9998.

Объёмы и счётчики приведены логарифмической шкалой к единичному порядку, читаемость поделена на
100, доли 0-1 оставлены как есть. После этого:

| Случай | Было | Стало |
|---|---|---|
| Идеальное совпадение | 0,9999 | 1,0000 |
| Стиль совпал, объём вдвое меньше | 0,9999 | 0,9963 |
| Объём совпал, стиль детский вместо научного | 0,9998 | 0,6408 |

Масштабы полей заданы константами в `Specifications`. Добавили поле — добавьте и его масштаб.

## Раскладка

| Каталог | Что внутри |
|---|---|
| `RoutedElements` | `BaseRoutedElement` — кандидат на исполнение: цены, скорость, обучаемый вектор соответствия |
| `JudgeLogic` | `Judge`, `Specifications`, `DiffSpec` — оценка и критика результата |
| `Services` | `SpecInputService` / `SpecOutputService` (ТЗ и факт), `TextMetrics`, `InputFeaturesService` |
| `LLM` | обращения к модели: извлечение ТЗ из запроса, распознавание стиля и лексики |
| `RotationTracking` | `InputFeatures`, `Tracert`, `Feedback` — признаки хода и данные для обучения |
| `Enums` | `Style`, `FeedbackType` |
| `Env`, `Settings` | среда соревнования кандидатов и общие настройки |

Пространство имён совпадает с каталогом: `FAI.Router.JudgeLogic`, `FAI.Router.Services` и так далее.

## Настройка

Клиент модели назначается один раз при старте, до обращения к сервисам распознавания:

```csharp
Settings.LLM = new LLMWithOpenRouterClient(new LLMOptions
{
    ApiKey = "...",
    ModelName = "openai/gpt-4o-mini"
});
```

Не назначен — обращение к `Settings.LLM` бросит `InvalidOperationException` с внятным текстом, а не
`NullReferenceException` из глубины вызова.

Остальное в `Settings`: веса `WQ` / `WC` / `Wt` и размерности пространства признаков. Размерность
спецификации (`FeaturesSpecDim`) вычисляется из перечисления `Style` и числа метрик, а не задаётся
константой, — иначе она расходится с вектором при добавлении полей.

`AIFramework3Open`: ссылки на него относительные.

| Ссылка | Зачем |
|---|---|
| `AI` | `Vector`, `Matrix` |
| `AI.LLM` | клиент OpenRouter, structured output, автоград и оптимизаторы (`V2`) |

```bash
dotnet build CSharp/src/FAI.Router/FAI.Router.csproj
```

## Состояние

Работает:

* ранжирование кандидатов по R;
* извлечение ТЗ из запроса одним обращением к модели (structured output, схема строится из
  перечисления `Style`, поэтому не расходится с ним);
* замер фактической спецификации: структура арифметикой, стиль и лексика моделью;
* оценка судьи и режим критика с построчным разбором расхождений.

Ещё нет:

* **обучения**: ни `IdealMatchVector`, ни `TransformerW` пока никто не обновляет. `Tracert` и
  `Feedback` — структуры без потребителя. Инструменты для этого есть в
  `AI.NeuralNetworks` (`AI.ML.NeuralNetworks.V2`): готовая дифференцируемая `CosineSimilarity`,
  `MSE`, `SGD`/`Adam`/`RMSProp` и планировщики LR;
* `Env.GetTopK` не заполняет `InputSpecifications`, поэтому при реальном роутинге спецификация в
  вектор признаков не попадает — заполняются только объёмные поля;
* `Judge.GetSpec` не реализован, хотя `SpecOutputService` делает ровно его работу;
* `IdealMatchVector` инициализируется константой, а не по Ксавье.
